Demo loads establish one cookie before concurrent requests; expiry, malformed cookies and cleanup pagination are covered.

- **Fixed — deployment/tooling:** Worker asset binding and API routing, root Pages discovery/imports, Docker shared modules, Vite same-origin proxy, Node 24 startup/cleanup, Docker metadata flavor syntax and actual CI build/test commands. ## Remaining limits

1. `server/hono-app.js` / `kvStore`: KV remains eventually consistent, rate-limited per key and non-transactional across Worker isolates. Concurrent writers can lose updates; rapid saves can fail. Local serialization cannot solve those platform guarantees. SPEC explicitly records the limitation; a stronger storage architecture remains a separate design decision. File storage similarly assumes one server process per data directory.
2. `client/src/utils.js` / `nextCardDate`: historical payments without `creditCardId` can only match the current card name. Same-name cards and historical renames remain ambiguous; new linked payments are fixed, and no guessed migration rewrites old records.
3. Complete translations and browser behavior are verified; independent native-language editorial review was not performed. Chromium verification does not claim exhaustive browser/assistive-technology coverage.
4. No built-in account authentication exists outside demo mode; this remains a single-account application requiring protected deployment. External authentication settings, distributed edge limits and live Cloudflare/GitHub behavior were not changed or certified by local checks.

Location: `server/dataService.js:14–15,77–80,113–136,153–180`; startup caller `client/src/App.jsx:49–69`. The stored-collection check reuses new-write validation. Fresh review reproduction on the recorded HEAD: seed a disposable `recurring.json` (or Hono MemoryKV `recurring`) with `[{"name":"<201 ASCII characters>","amount":1750.5,"type":"debit","dayOfMonth":31,"id":"1720000000000","createdAt":"2024-07-03T09:46:40.000Z"}]`, replacing the name placeholder with `"a".repeat(201)`. Fix direction: preserve existing long, nonblank names on reads and unrelated/identical-name updates; retain strict new/changed-name validation and all unrelated corruption checks. Handle all three collections, deletion, clear-all and other-record mutations. Do not truncate data automatically. ### RC2 — DIVERGENCE: Proxy identity and HTTPS are not recognized

Location: `server/app.js:19–33,56–61,119–125`, `server/index.js:11`. Express leaves proxy trust disabled while its entrypoint listens over HTTP. A TLS-terminating reverse proxy therefore does not cause `req.secure` to become true, and forwarded clients share the proxy's rate-limit bucket. This violates SPEC §I.53 and §V.3.

Fresh review reproduction on the recorded HEAD: use disposable Express data and a node:http request preserving `Host: finance.example`, `Origin: https://finance.example`, `X-Forwarded-Proto: https` and `X-Forwarded-For: 203.0.113.1`. `GET /api/settings` in demo mode returns 200 and an HttpOnly/SameSite=Strict/Path=/ cookie with Max-Age=432000, without Secure. On a fresh app, 300 settings requests forwarded for `203.0.113.1` return 200; the first request forwarded for `203.0.113.2` returns 429. The limiter logs `ERR_ERL_UNEXPECTED_X_FORWARDED_FOR`.

Fix direction: add explicitly scoped proxy-address configuration before middleware, preserving direct/untrusted behavior and both limiters. Verify HTTPS cookie flags, independent client quotas, forwarding-chain spoof resistance and static-only loopback exemptions. Do not enable blanket trust or disable limiter validation. Document header replacement and Host preservation at the trusted proxy. Primary sources checked 2026-10-03: [Express behind proxies](https://expressjs.com/en/guide/behind-proxies/) and [express-rate-limit error codes](https://express-rate-limit.mintlify.app/reference/error-codes#err-erl-unexpected-x-forwarded-for). Remediation mapping: F2.T1–T2; final acceptance F3.T1.
